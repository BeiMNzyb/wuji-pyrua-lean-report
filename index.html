PyRUA-Lean × WUJI SimBench 真实闭环复现报告

本页只把 WUJI 官方 checker 的真实自主闭环结果计为本项目成功率。论文在其他基准的数字、示范轨迹和单个视频不代替本项目的分母或成功率。

能力组：RGB-D + pyroki IK + 规划器视觉选点；不使用 ACT/VLA。SAM3 权重许可检查失败，因此本组没有 locate/segment。没有训练 PyRUA-Lean。

方法与架构

规划模型编写持久 Python cells；robo 原语执行动作并返回结构化测量结果。一个 cell 可以检查到位误差、条件重试并只按需请求图像。沙箱限制导入和文件访问，调用/时间预算约束执行。agent 框架、规划模型、基础原语和可选 ACT/VLA 是不同层。

正式协议

  • 物理：Isaac Sim 5 / PhysX；渲染：Isaac raytracing；机器人：tianji_wuji，54 个命名位置关节，100 Hz。
  • 规划器：固定 revision 的 PyRUA-Lean Coder v0.1-4B；不训练、无跨 episode 记忆。
  • cells 与 tool-calling 使用同一规划器、原语、实例、后端、渲染和 checker；每种接口最多 40 次规划调用、5400 秒墙钟。
  • 每任务每接口 20 个不同初始实例；先官方 eval，再以未用于预试的 train 补足并明确标记，不把 train split 冒充 held-out。实例 ID 和场景 checksum 都不得重复。
  • 启动失败、planner error、动作异常、超时均保留在分母并单列。成功仅来自官方 checker 的逐 tick latch。

限制、碰撞与后续审查

  • SAM3 权重许可未通过，因此使用显式 RGB-D 基础原语，不能与 SAM3 方案比较成功率。
  • IK 使用 coarse self-collision 模型且 recording parity 权重为 0；真实 USD 警告、关节漂移和穿模不能仅从视频外观排除，应结合日志审查。
  • 所选任务结果不能外推到整个 WUJI。4B 规划器与论文 GPT-6 Astra 不同。
  • 适配代码先留在独立工作区。建议审查信息边界、54 维映射、坐标变换和测试后，再在专用 worktree 提交小 PR；本次未合并。
